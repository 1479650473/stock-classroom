## 1. 核心循环全景 (架构图落地对照)

```
[数据引入] 行情K线(kline.db) + 趋势/基本面(fundamental.db)
     ↓
[策略构思] 多因子复合判断 = 技术面(BP) + 基本面(EP/BP/ROE) + 消息面(LLM深挖) + 事件驱动
     ↓
[权重计算] regime 动态化(牛/熊/震荡 → 因子权重调整)      ← 第2期A
     ↓
[周期性策略轮换] 判断器驱动(牛→B反转进攻 / 震荡→F价值Tilt / 熊→C低波动防守)   ← 已自动切换模拟盘
     ↓
[回测] 完整生命周期验证 + 分周期测试(牛/熊/震荡/全周期) + 样本内/样本外(防过拟合)   ← cycle_test
     ↓
[模拟盘] 多策略独立账户 + 轮动账户(宏观分析器驱动) + 全策略对比
     ↓
[每日复盘] update_daily 自动: 数据→regime→事件池→个股深挖→持仓守护→净值快照
     ↓
[LLM介入] 个股资讯深挖(主观判断) + 事件驱动池(突发利好, isolated) + 策略进化(optimize_loop)
     ↓
[卖出门] 条件止损 + 移动止损 + 策略卖出(三驱动, 无固定止盈)   ← 用户哲学
```

**对照用户架构图**: 常规交易结构(买→卖→结算→盈亏→迭代) + 量化交易结构(构思→回测→模拟盘→生效) +
策略构成(多因子/权重/周期轮换) + 软件结构图(主循环/回测架构/模拟盘架构) —— 全部落地。

## 2. 卖出门 — 三驱动 (用户策略哲学, 已定死)

**不加固定止盈(让利润奔跑)**, 用三驱动:
| 驱动 | 默认参数 | 作用 |
|---|---|---|
| ① 条件止损 | 8% | 兜底防大亏(跌破即走) |
| ② 移动止损 | 10%回撤 / +15%激活 | 利润奔跑后锁利(创新高止损线上移) |
| ③ 策略卖出/重平衡调出 | 排名掉出 top_k% | 信号/排名失效才兑现 |

**卖出优先级**: 止损 > 移动止损 > 重平衡调出 > 止盈(默认关)。

### 实现 (backend/strategy/)
- **sell_rules.py**: `SellRuleSet.build(rebalance_bars, top_k_pct, stop_loss_pct=0.08, take_profit_pct=0, trailing_stop_pct=0.10, trailing_activation_pct=0.15)` — 单一事实来源。
  `time_limit_bars` 默认 0(不设时间止损: 与重平衡周期同长会每期清仓致 rebalance_exit 永不触发)。
- **position_guard.py**: `PositionGuard(rule_set)` 用 `protection.ProtectionEngine` 对单持仓逐日判定。
- **day_guard.py**: `run_day_guard(dry_run=True)` 每日读模拟账户持仓→K线→恢复持有期→触发卖出。
  默认 dry_run 预览(防自动清仓误伤), `--execute` 才真卖。落库 `data/day_guard_log.json`。
- **前端 trade 持仓表**: 加"卖出条件"列(触发红'止损'/绿'移动止损', 未触发灰'保护中')。

### 验证结果 (真实 287 池, 2024-01→2026-08, F价值Tilt)
| 方案 | 总收益 | 夏普 | 回撤 |
|---|---|---|---|
| 无保护(纯重平衡) | +40.2% | 0.192 | -19.0% |
| **三驱动(8%止损+移动止损+策略卖出)** | **+36.3%** | **0.209** | **-12.9%** |
→ 收益小降3.9pp, 回撤大降6.1pp, 夏普升 = **用一点收益换大幅控回撤(正确取舍)**。

> ⚠️ 教训: **5% 止损是负优化**(高波动287池日波±3-5%, 正常波动就被误杀割肉, 高买低卖反复放血
> 把 +63.5% alpha 亏成 -79.3%)。卖出风控必须匹配池子波动率。此教训已记入 skill。

## 3. 完整回测指标标准 (用户要求, 39848ba + 781a05e)

**完整回测数据**必须包含以下全维指标(缺一不可):

| 指标 | 含义 | 键名 |
|---|---|---|
| **日期区间隔离** | 起止日期(非净值) | `start_date`/`end_date` |
| **夏普率** | 风险调整收益 | `sharpe` |
| **阿尔法** | 年化超额收益 | `alpha` |
| **贝塔** | 市场风险暴露 | `beta` |
| **伽马** | 信息比率 = 年化超额 / 年化跟踪误差 | `gamma` |
| **收益率** | 总收益 + 年化CAGR | `total_return`/`cagr` |
| **交易频率** | 年均完整换手次数 | `turnover_yearly` |
| **交易总次数** | 卖出笔数 + 全部成交流 | `num_trades`/`total_trades` |
| **胜率** | 盈利卖出占比 | `win_rate` |
| **盈亏比** | 总盈利/总亏损 | `profit_factor` |
| **其他** | 索提诺/Calmar/波动/最大回撤/超额/基准 | `sortino`/`calmar`/`volatility`/`max_drawdown`/`excess_return`/`bench_return` |

### 实现
- **metrics.py `full_metrics(nav, bench, freq_bars, dates)`**: 加 `dates` 参数(存 `start_date/end_date`,
  原 `start/end` 存净值是 **bug** 已修)+ 加 `gamma` 信息比率(年化超额/年化跟踪误差)。
- **metrics.py `compute_full_metrics(nav, bench, freq_bars, trades, dates)`**: 加 `trades` 参数, 统计
  `num_trades/win_rate/profit_factor/turnover_yearly/total_trades`; 传 `bench` 才算出 `alpha/beta/gamma`。
- **verify_full_lifecycle / cycle_test**: 调 `compute_full_metrics` 传 `bench(买持)` + `trades` + `dates` →
  完整指标全部输出。
- **portfolio_rebalance.forward_paper_run**: 加 `cost_basis`(加权成本单价)追踪, 卖出时记录 `pnl`。
- **research/worker.py `_flatten_rebalance_trades`**: rebalance_log 摊平为成交流 → 生产 paper 也带完整指标。
- **前端 holdings 摘要卡**: 7项→12项(累计收益/年化α/β/γ信息比/年化收益/夏普/索提诺/胜率/盈亏比/回撤/交易次数/年换手)。

> ⚠️ **关键坑(已修)**: forward_paper_run 若在 rebalance_log **二次遍历**时依赖 cost_basis(已 pop) →
> 卖出 pnl 全算 0(胜率0/盈亏比0失真)。**必须在第一次循环记录正确 pnl**(卖出价-加权成本)*数量。

## 6. ⚠️ F价值Tilt vs D多因子 — 根因已查明+修复 (7f578a0)

**早期现象**: 两者数据完全一样 → 用户质疑「D和F怎么完全一样」。
**根因**: 两者 factors/weights **完全相同**(BP+REVERSAL+VOLATILITY, 权重1/1/-1), 唯一差异 `use_tilt`
(F=True / D=False)。但 `_real_signals` 的 **value_spread 恒 None** → 三路信号(index负+breadth正)打成
**平局** → `w_value` 恒 = 1.0(中性) → **F 的价值 tilt 形同虚设** → F = D。

**修复 (7f578a0)**: 激活 value_spread 信号。
- `RebalancePlanner._calc_value_spread(frames, date)`: 用 BP 因子 longShort 曲线近 4 重平衡期价差
  (>0 顺风=1.0 / <0 逆风=0.0 / 数据不足=None, 与 research_loop.portfolio_paper 同生产口径)。
- longShort 曲线 `_ls_cache` 整段缓存(仅首次算, 避免逐调仓日重跑因子研究, 否则性能崩)。
- `plan_at`: use_tilt 且 value_spread=None 时补算 → `portfolio_value_alloc` → w_value 在
  **1.5(顺风)/0.3(逆风)/1.0(中性)** 间摆动。

**效果**: F 价值Tilt w_value 在 0.3/1.5 摆动, **F +35.1% vs D +41.8% 彻底区分**。
> 价值tilt=权重受大盘周期控制(架构图核心), 此前一直未真激活。
> ⚠️ value_spread 依赖 BP 因子 longShort 曲线(需 BP 数据 2023 起), 2020 年无数据→None(中性)。

## 7. 回测逻辑口径 — K线 vs Tick (重要, 用户曾问)

**当前系统是日K线回测(daily bar backtest), 不是 Tick 回测**。

### 依据
- `_load_frames` 从 kline.db 加载**日K线**帧(287池, ~1516交易日)。
- `FactorResearchEngine._panel` 拼成**日 OHLC 面板**(1516×287)。
- `forward_paper_run`/`verify_full_lifecycle` 逐**日**回放, 每 20 根日K线重平衡, 订单在重平衡日
  按**收盘价**成交。
- `ProtectionEngine.evaluate_bar(bar, state)` 输入**日K线 bar**(open/high/low/close)。
- `hs300.json`(regime 判断)也是日线序列。

### 口径边界
| 维度 | 日K线能捕捉 | 日K线**看不到** |
|---|---|---|
| 择时 | 日级别趋势/反转 | 盘中波动、日内动量 |
| 止损 | 收盘触及阈值 | **盘中跌破止损点**(当天跌到又收回, 日K线看不出) |
| 成交 | 按收盘价 | 涨停买不进/跌停卖不出、滑点 |
| 指标 | 日频夏普/α/β/γ | 分钟级高频指标 |

> 升级 Tick 需引入日内数据源(akshare 分钟/Level-2) + 重写撮合引擎(盘口/滑点/涨跌停)——大工程。

## 8. 回测引擎流程 — 现状 vs 用户最新架构图 (2026-08-30)

用户最新画的**回测引擎内核流程**(标准事件驱动回测):
```
配置回测参数(起止/初始资金/手续费/滑点)
 → 加载&预处理历史行情(复权、清理异常数据)
 → 回测引擎初始化账户、订单队列
 → 遍历每一个时间切片(K线/Tick)  ← 菱形
 → 把当前切片喂给策略(仅允许当前及历史数据, 禁止未来数据)
 → 执行策略逻辑(计算指标、生成买卖信号、生成订单)
 → 模拟撮合模块(校验资金、涨跌停、滑点手续费, 判断订单是否成交)
 → 成交?  ← 菱形
     是 → 更新账户状态(现金/持仓/总资产), 记录交易日志
     否 → 跳过本次成交, 保留挂单
 → 是否还有下一个时间切片?  ← 菱形
     是 → 回到"遍历每一个时间切片"
     否 → 回测结束, 计算净值/最大回撤/夏普/胜率等指标
 → 输出报告、绘图、评估策略效果
```

### 现状逐项对照
| 流程节点 | 现状实现 | 状态 |
|---|---|---|
| 配置回测参数 | `verify_full_lifecycle(..., start, end)` 有起止/资金/fee | ✅ |
| 加载&预处理(复权) | akshare 三源回退有复权; 无显式清异常 | 🟡 |
| 初始化账户 | 有账户(初始balance/cash) | ✅ |
| **订单队列** | **无** | 🟡 |
| 遍历时间切片 | 只日K线逐bar, 无Tick | 🟡 |
| 喂给策略(禁止未来) | `plan_at(date)` 只用 ≤date 数据 | ✅ |
| 执行策略(生成信号/订单) | `composite_score`→`select_top_k`→trades | ✅ |
| **模拟撮合(涨跌停/滑点)** | `_do_buy/_do_sell` 按**收盘价直接成交**; 校验资金; **无涨跌停、无滑点** | 🟡 |
| **成交? 保留挂单** | 资金够即成交; **无"不成交保留挂单"分支** | ❌ |
| 回测结束算指标 | `compute_full_metrics` 完整输出 | ✅ |
| 输出报告/绘图 | 落库 + 持仓页曲线 | ✅ |

### 关键差距(待补)
1. **❌ 模拟撮合不真实**(最关键): 无涨跌停校验(A股涨停买不进/跌停卖不出, 影响极大)、无滑点
   (slippage 只在参数里没真用)、无挂单队列(成交/不成交分支完全没有)。
2. **🟡 只有日K线, 无 Tick**: 用户图明确"K线/Tick", 现状只支持日线。
3. **🟡 无"清理异常数据"预处理**: 无显式去异常(停牌/复牌跳空/数据缺失)。

## 9. 数据地基 — 2023 K线缺口修复

**根因**: kline.db 2023年K线大面积缺失(全市场仅2173只, 宽池287只里240只缺2023) →
BP因子面板2023仅覆盖40/287只 → 2023区间回测失真。

**修复**: ①`_load_frames` limit 1200→2600(覆盖WARM 2020前warmup) ②池内240只补齐(ok240 fail0 新增55万行)。

**效果**: BP覆盖 40→223/287; 全周期 -25.8%(虚假)→**+98.3%**(真实)。样本外+25%未过拟合。
> **数据是地基**: 验证若异常差, 先查K线覆盖再怀疑策略(分周期测试的价值: 顺带揪出数据管道缺陷)。

## 13. 关键纪律 (防再踩坑)
1. **卖出风控匹配池子波动率** —— 5%止损在高波动池=负优化, 用8%+移动止损。
2. **验证器保护bar用真实OHLC** —— high/low=0 会导致全触发止损误报。
3. **对比验证用同一区间** —— 完整区间 vs 短区间结果差异巨大。
4. **纯因子策略防截面退化** —— A价值在基本面稀疏时会退化成少数股票(虚高)。
5. **数据是地基** —— 验证异常差先查K线/基本面覆盖。
6. **价值tilt需value_spread信号** —— 无信号则三路平局w_value恒1.0, tilt形同虚设(F=D)。
7. **pnl必须在第一次循环记录** —— 二次遍历依赖已pop的cost_basis会全算0。
